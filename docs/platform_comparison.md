# Сравнительный анализ платформ: GitHub и GitFlic

**Выбор для проекта: GitHub.** Причины: в уровне 3 лабораторной используется GitHub Actions;
подробная документация и шаблоны Issue/Pull Request в стандартном формате; привычный
интерфейс; бесплатный тариф достаточен для учебного проекта.

**Альтернатива для сравнения: GitFlic** — российская DevOps-платформа, включена в Единый реестр
российского ПО (№15861 по методичке), доступна в облачном и локальном вариантах.

> Сравнение построено на описании платформ в методических материалах и общих сведениях; перед
> сдачей сверьте пункты с актуальной документацией платформ (ссылки в `docs/russian_git_analogs.md`):
> функции и условия доступа меняются.

| Критерий | GitHub | GitFlic |
|----------|--------|---------|
| Происхождение | зарубежная облачная платформа | российская платформа из Единого реестра ПО |
| Хранение кода | Git, облако (есть корпоративная установка за отдельную плату) | Git, облако и локальная установка |
| CI/CD | GitHub Actions (`.github/workflows/*.yml`), большой каталог готовых действий | встроенные средства CI/CD со своим форматом конфигурации; конфигурацию GitHub Actions придётся переписать |
| Pull Request / ревью | развитое: ревью по строкам, обязательные проверки, защита веток | базовые возможности запросов на слияние и ревью |
| Шаблоны Issue/PR | поддерживаются файлами в `.github/` | настраиваются средствами платформы; формат файлов может отличаться |
| Экосистема и интеграции | очень большая: сторонние сервисы, боты, Dependabot | меньше интеграций, экосистема развивается |
| Документация и сообщество | обширная, много материалов на русском и английском | документация на русском языке, сообщество меньше |
| Интерфейс | привычный большинству разработчиков | похож на другие Git-платформы; на русском языке |
| Соответствие требованиям импортозамещения | не входит в реестр российского ПО | входит в реестр |
| Доступность | зависит от текущих ограничений и условий сервиса | работает на территории РФ, возможна установка на собственные серверы |

## Преимущества и недостатки

**GitHub** — плюсы: зрелая экосистема, Actions, лучшая документация. Минусы: не входит в реестр
российского ПО, зависимость от иностранного сервиса и его условий.

**GitFlic** — плюсы: соответствие требованиям импортозамещения, возможность локальной установки,
русскоязычная поддержка. Минусы: меньше интеграций и готовых примеров, отличия в конфигурации CI/CD.

## Вывод

Для учебного проекта с CI на GitHub Actions удобнее GitHub. Для организаций, обязанных использовать
отечественное ПО, или при необходимости хранить код на своих серверах разумнее GitFlic или другая
платформа из реестра; процесс работы (ветки, коммиты, слияния) при этом остаётся тем же, так как
обе платформы построены на Git.
