## BUG-1. Вывод матрицы теряет точность (только 6 значащих цифр, «-0»)

- **Модуль:** `io_utils.format_matrix`
- **Обнаружен тестами:** TC-F-03 … TC-F-06, test_format_does_not_change_value
- **Метод:** граничные значения (6 значащих цифр)
- **Серьёзность / приоритет:** высокая / высокий
- **Шаги воспроизведения:** Вызвать `format_matrix([[1234567.0, 0.1234567891, -0.0]])`.
- **Ожидаемый результат:** `1234567  0.1234567891  0` — числа совпадают с введёнными.
- **Фактический результат:** `1.23457e+06  0.123457  -0` — тихое искажение данных: в отчёте не те числа, что ввёл пользователь.
- **Исправление:** `format_matrix` использует кратчайшую запись числа (`repr`), `.0` у целых убирается, `-0.0` выводится как `0`.
- **Коммит исправления:** «Исправление BUG-1: вывод матрицы без потери точности»
- **Регрессионный тест:** `test_bug1_format_keeps_precision`
- **Статус:** исправлен, проверен повторным прогоном

## BUG-2. Огромное целое число в JSON вызывает OverflowError

- **Модуль:** `mapping.dto_to_matrix (и REST-сервис)`
- **Обнаружен тестами:** TC-M-10, TC-M-11, TC-R-08
- **Метод:** граничные значения (больше `float`) + предположение об ошибке
- **Серьёзность / приоритет:** высокая / высокий
- **Шаги воспроизведения:** Вызвать `dto_to_matrix` с элементом `10 ** 400`; либо отправить такой JSON сервису.
- **Ожидаемый результат:** `InvalidDataError` с понятным сообщением; сервис отвечает кодом 400.
- **Фактический результат:** `OverflowError: int too large to convert to float`; в сервисе обработчик падает и соединение обрывается без ответа.
- **Исправление:** Приведение к `float` перенесено в функцию `_to_float` внутри `try`; переполнение превращается в `InvalidDataError("…число слишком велико.")`.
- **Коммит исправления:** «Исправление BUG-2: слишком большие целые числа отвергаются с InvalidDataError»
- **Регрессионный тест:** `test_bug2_huge_integer_is_rejected_not_crashing`
- **Статус:** исправлен, проверен повторным прогоном

## BUG-3. Отрицательный Content-Length подвешивает обработчик сервиса

- **Модуль:** `server.ProcessingHandler`
- **Обнаружен тестами:** TC-R-05
- **Метод:** граничные значения (длина < 0)
- **Серьёзность / приоритет:** высокая / высокий
- **Шаги воспроизведения:** Отправить `POST /api/v1/process` с заголовком `Content-Length: -1`.
- **Ожидаемый результат:** Ответ 400 (`invalid_request`).
- **Фактический результат:** Обработчик ждёт данные «до конца потока», ответ не приходит (таймаут клиента).
- **Исправление:** Заголовок проверяется: нечисловое и отрицательное значения → `InvalidDataError` → 400.
- **Коммит исправления:** «Исправление BUG-3, BUG-4: проверка Content-Length и предел размера тела 1 МиБ»
- **Регрессионный тест:** `test_bug3_negative_content_length_gives_400`
- **Статус:** исправлен, проверен повторным прогоном

## BUG-4. Размер тела запроса не ограничен

- **Модуль:** `server.ProcessingHandler`
- **Обнаружен т


естами:** TC-R-07
- **Метод:** граничные значения (1 МиБ + 1)
- **Серьёзность / приоритет:** высокая / средний
- **Шаги воспроизведения:** Отправить запрос с `Content-Length: 1048577` и не присылать тело.
- **Ожидаемый результат:** Ответ 413 (`payload_too_large`) сразу, без чтения тела.
- **Фактический результат:** Сервис ждёт тело заявленной длины без ограничений (отказ в обслуживании). Замечание №3 инспекции ЛР №3 («размер тела не ограничен») подтверждено тестом.
- **Исправление:** Введена константа `MAX_BODY = 1024 * 1024`; при превышении — ответ 413.
- **Коммит исправления:** «Исправление BUG-3, BUG-4: проверка Content-Length и предел размера тела 1 МиБ»
- **Регрессионный тест:** `test_bug4_oversized_body_gives_413_and_limit_is_inclusive`
- **Статус:** исправлен, проверен повторным прогоном

## BUG-5. Некорректный адрес сервиса даёт вводящую в заблуждение ошибку

- **Модуль:** `http_client.process_remote`
- **Обнаружен тестами:** TC-C-01 … TC-C-04
- **Метод:** предположение об ошибке (опечатка в адресе)
- **Серьёзность / приоритет:** средняя / средний
- **Шаги воспроизведения:** Вызвать `process_remote(m, "localhost:8080")`; затем с пустым адресом.
- **Ожидаемый результат:** `InvalidDataError`: адрес должен начинаться с http:// или https:// и содержать хост.
- **Фактический результат:** `ModuleUnavailableError: Сервис недоступен: unknown url type: localhost`; для пустого адреса — необработанный `ValueError`.
- **Исправление:** Функция `_check_arguments` проверяет схему и хост (`urlsplit`) до сетевого вызова.
- **Коммит исправления:** «Исправление BUG-5, BUG-6: проверка адреса сервиса и таймаута до запроса»
- **Регрессионный тест:** `test_bug5_bad_service_address`
- **Статус:** исправлен, проверен повторным прогоном

## BUG-6. Некорректный таймаут (≤ 0, nan) обрабатывается неверно

- **Модуль:** `http_client.process_remote`
- **Обнаружен тестами:** TC-C-05 … TC-C-07
- **Метод:** граничные значения (таймаут = 0) + предположение об ошибке
- **Серьёзность / приоритет:** средняя / средний
- **Шаги воспроизведения:** Вызвать `process_remote(m, url, -1)`, затем с `0` и `float('nan')`.
- **Ожидаемый результат:** `InvalidDataError`: «Таймаут должен быть положительным числом секунд».
- **Фактический результат:** Для −1 и nan — «Некорректный ответ сервиса: Timeout value out of range / Invalid value NaN», хотя ответа не было; для 0 — «Сервис недоступен: Operation now in progress».
- **Исправление:** Проверка `not timeout > 0` в `_check_arguments` (отсекает и 0, и nan).
- **Коммит исправления:** «Исправление BUG-5, BUG-6: проверка адреса сервиса и таймаута до запроса»
- **Регрессионный тест:** `test_bug6_bad_timeout`
- **Статус:** исправлен, проверен повторным прогоном

## BUG-7. Разделитель разрядов «_» принимается как часть числа

- **Модуль:** `io_utils.parse_matrix`
- **Обнаружен тестами:** TC-G-01, TC-G-02
- **Метод:** предположение об ошибке
- **Серьёзность / приоритет:** низкая / средний
- **Шаги воспроизведения:** Ввести матрицу `1 2` / `1_0 2`.
- **Ожидаемый результат:** Ошибка «не удалось прочитать число».
- **Фактический результат:** Принято как `[[10.0, 2.0]]`: опечатка проходит незамеченной (особенность `float()` в Python).
- **Исправление:** `_parse_number` отвергает токены, содержащие «_».
- **Коммит исправления:** «Исправление BUG-7, BUG-8, BUG-9: строгий разбор чисел и заголовка, чтение UTF-8 с BOM»
- **Регрессионный тест:** `test_bug7_underscore_in_number_is_rejected`
- **Статус:** исправлен, проверен повторным прогоном

## BUG-8. Не-ASCII цифры в заголовке «n m» дают сообщение интерпретатора

- **Модуль:** `io_utils.parse_matrix`
- **Обнаружен тестами:** TC-G-03, TC-G-04
- **Метод:** предположение об ошибке
- **Серьёзность / приоритет:** низкая / низкий
- **Шаги воспроизведения:** Ввести заголовок `² 1` или `٣ ١`.
- **Ожидаемый результат:** «Первая строка должна содержать два целых числа: n m».
- **Фактический результат:** `ValueError: invalid literal for int() with base 10: '²'` (для арабо-индийских цифр заголовок п


ринимается, но дальше следует нелогичная ошибка о числе строк).
- **Исправление:** В проверке заголовка добавлено `t.isascii() and t.isdigit()`.
- **Коммит исправления:** «Исправление BUG-7, BUG-8, BUG-9: строгий разбор чисел и заголовка, чтение UTF-8 с BOM»
- **Регрессионный тест:** `test_bug8_non_ascii_digits_in_header`

## BUG-9. Файл в кодировке UTF-8 с BOM не читается

- **Модуль:** `io_utils.read_matrix_file`
- **Обнаружен тестами:** TC-G-08
- **Метод:** предположение об ошибке
- **Серьёзность / приоритет:** средняя / высокий
- **Шаги воспроизведения:** Сохранить `examples/input1.txt` в Блокноте Windows как «UTF-8 с BOM» и запустить программу.
- **Ожидаемый результат:** Файл читается как обычно.
- **Фактический результат:** «Первая строка должна содержать два целых числа: n m» — символ `\ufeff` портит заголовок.
- **Исправление:** Файл открывается в кодировке `utf-8-sig`.
- **Коммит исправления:** «Исправление BUG-7, BUG-8, BUG-9: строгий разбор чисел и заголовка, чтение UTF-8 с BOM»
- **Регрессионный тест:** `test_bug9_utf8_bom_file_is_read`
- **Статус:** исправлен, проверен повторным прогоном
