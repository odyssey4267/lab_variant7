# Обзор российских аналогов Git из Единого реестра российского ПО

Единый реестр российского программного обеспечения — государственная информационная система со
сведениями об отечественных программных продуктах, рекомендованных к использованию в государственных
и коммерческих организациях (https://reestr.digital.gov.ru/). Большинство перечисленных ниже продуктов
построено на стандарте Git, поэтому привычные команды (`clone`, `commit`, `push`, `merge`) и процесс
работы остаются прежними.

> Описание составлено по методическим материалам и официальным сайтам продуктов. Перед использованием
> проверьте актуальные возможности на сайтах (ссылки приведены в конце): набор функций и условия
> лицензирования меняются.

| Продукт | № в реестре | Назначение |
|---------|-------------|-----------|
| GitFlic | 15861 | DevOps-платформа для хранения кода и совместной разработки, позиционируется как альтернатива GitLab; облачный и локальный варианты |
| GitFlame | 21590 | сервис хранения репозиториев с версионным контролем исходного кода для разработчиков и DevOps-инженеров; построен на Git |
| Gitlife Enterprise | 29396 | модульная платформа управления полным жизненным циклом проектов; модуль «Код» на базе Git |
| Deckhouse Code | 27871 | решение для непрерывной разработки и управления жизненным циклом ПО; хранение кода и CI/CD |
| EvaGit (платформа EvaTeam) | в составе EvaTeam | система управления Git-репозиториями: ветки, коммиты, pull-реквесты, код-ревью |
| Mos.Hub | городской проект | репозиторий ПО с открытым кодом, позиционируется как аналог GitHub для российских разработчиков |

## Функциональные возможности

- **GitFlic** — репозитории Git, совместная работа над кодом, средства DevOps (в том числе конвейеры),
  установка в облаке или на собственных серверах.
- **GitFlame** — хранение репозиториев и контроль версий для разработчиков и DevOps-инженеров.
- **Gitlife Enterprise** — управление проектом целиком (планирование, задачи, код); для работы с
  исходниками используется модуль «Код» на базе Git.
- **Deckhouse Code** — хранение кода вместе с инструментами CI/CD, ориентирован на непрерывную разработку.
- **EvaGit** — ветки, коммиты, pull-реквесты и код-ревью внутри платформы EvaTeam; удобен, если команда
  уже использует EvaTeam для задач и процессов.
- **Mos.Hub** — публичный хостинг проектов с открытым кодом; удобен для открытых проектов и обучения.

## Преимущества

- включение в реестр российского ПО — соответствие требованиям импортозамещения;
- совместимость с Git: не нужно переучиваться, можно мигрировать существующие репозитории;
- русскоязычные интерфейс, документация и техническая поддержка;
- возможность локальной установки (для большинства продуктов) — код остаётся на серверах организации.

## Ограничения

- экосистема интеграций и готовых примеров меньше, чем у GitHub и GitLab;
- форматы конфигурации CI/CD отличаются от GitHub Actions, готовые конвейеры придётся адаптировать;
- набор функций у разных продуктов неодинаков (например, у EvaGit — часть платформы EvaTeam, у
  Gitlife Enterprise — часть более широкой платформы управления проектами);
- Mos.Hub — городской проект с открытым кодом, а не коммерческая платформа для закрытой разработки.

## Выводы

Для государственных и коммерческих организаций, которым нужны отечественное ПО и контроль над данными,
подходят GitFlic, GitFlame, Gitlife Enterprise, Deckhouse Code, EvaGit; для открытых и учебных проектов
— Mos.Hub. Выбор определяют требования к CI/CD, интеграциям и способу развёртывания.
