# Инспекция кода при тестировании (ЛР №4)

## 1. Статический анализ

Инструмент: **flake8** (`setup.cfg`: длина строки 100, сложность ≤ 10). Проверяются каталоги
`src`, `tests`, `tools`.

Первый запуск после написания тестов «белого ящика»:

```
tests/test_whitebox.py:168:49: E127 continuation line over-indented for visual indent
```

**Замечание:** продолжение строки в декораторе `parametrize` выровнено неверно (E127).
**Исправление:** таблица значений вынесена в константу `TIMEOUTS`; поведение теста не изменилось.
Повторный запуск — замечаний нет.

## 2. Что показало тестирование (сверх инструментов)

Линтер не находит логических дефектов; их выявили тесты. В `docs/bug_reports.md` — 9 дефектов.
Замечание №3 инспекции ЛР №3 («размер тела запроса не ограничен») подтверждено тестом TC-R-07 и
исправлено (BUG-4): предел 1 МиБ.

## 3. Ревью тестов

| Критерий | Результат |
|----------|-----------|
| У каждого тестового случая есть идентификатор, описание, входные данные и ожидаемый результат | ✔ |
| Ожидаемые результаты взяты из спецификации, а не из вывода программы | ✔ |
| Границы проверены с обеих сторон (на границе, внутри, снаружи) | ✔ |
| Тесты независимы и не зависят от порядка запуска | ✔ |
| Сервис поднимается на свободном порту, сетевые тесты ограничены по времени | ✔ |
| Для каждого дефекта есть тест, который падает на старом коде | ✔ |
