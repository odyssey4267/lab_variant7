# Сравнительный анализ методов тестирования

## Методы «чёрного ящика»

| Метод | Идея | Сильные стороны | Ограничения | Применение в проекте |
|-------|------|-----------------|-------------|----------------------|
| Эквивалентное разбиение | входы делятся на классы, из каждого берут один представитель | мало тестов, покрывает все классы | не видит ошибок на границах классов | неявно: классы «корректная матрица», «пустая», «нечисловая» |
| **Анализ граничных значений** (вариант 7) | значения на границе допустимой области и рядом с ней | дефекты чаще на границах (`<` vs `<=`, `n-1`/`n+1`, 6 значащих цифр) | нужны чёткие границы; не ищет «странные» входы | n, m = 0/1/2; длины строк; EPS; 1 МиБ; таймаут 0 — **BUG-1, 3, 4, 6** |
| **Предположение об ошибке** (вариант 7) | тесты строятся по опыту: где обычно ломаются | находит дефекты, которых нет в спецификации | зависит от опыта тестировщика, не формализуется | `-0.0`, `nan`, `1e309`, `1_0`, BOM, адрес без схемы — **BUG-2, 5, 7, 8, 9** |
| Причинно-следственные графы / таблицы решений | таблица «условия → действия» | полнота для сочетаний условий | быстро растёт с числом условий | для трёх условий варианта 7 избыточно |

## Методы «белого ящика»

| Метод | Критерий | Уровень строгости | Применение |
|-------|----------|-------------------|------------|
| Покрытие операторов | каждый оператор выполнен хотя бы раз | низкий | измеряется coverage.py |
| Покрытие решений (ветвей) | каждое решение стало и `True`, и `False` | средний | `--cov-branch`, таблицы D1–D8 |
| Покрытие условий | каждое простое условие принимало оба значения | средний | таблицы D1–D8 |
| Покрытие комбинаций условий | все комбинации значений условий внутри решения | высокий, 2^k тестов | для составных условий (`tests/test_whitebox.py`) |

## Вывод

Методы дополняют друг друга. Граничные значения дали самые «дорогие» дефекты (искажение вывода,
зависание сервиса), предположение об ошибке — «странные» входы (BOM, `1_0`), белый ящик показал,
какие ветви остались без проверки, а покрытие — что тестами охвачено не менее 80 %. Но высокое покрытие
не гарантирует качества тестов, поэтому качество проверено мутационным методом
(`docs/test_review.md`).
