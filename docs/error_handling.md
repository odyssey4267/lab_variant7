# Обработка исключительных ситуаций при интеграции (уровень 3)

Любой сбой взаимодействия превращается в типизированное исключение; управляющий модуль
(`app.run`) перехватывает `IntegrationError`, печатает сообщение в `stderr` и возвращает код,
заданный исключением.

| Ситуация | Исключение | Код возврата | Где обнаруживается |
|----------|-----------|--------------|--------------------|
| Некорректные данные (файл, ввод, JSON, матрица) | `InvalidDataError` | 1 | модули ввода и обработки, `mapping`, HTTP 400 |
| Недоступность модуля (отказ в соединении, обрыв связи) | `ModuleUnavailableError` | 2 | `http_client` |
| Таймаут (сервис не ответил за `--timeout` секунд) | `ModuleTimeoutError` | 3 | `http_client` |
| Конфликт версий API | `VersionConflictError` | 4 | `mapping.check_version`, HTTP 409 |

## Версионирование API

Каждое сообщение содержит поле `api_version` (сейчас `"1.0"`). Совместимыми считаются версии с той же
старшей частью (`1.x`). Сервис отвечает `409 Conflict`, если версия запроса несовместима; клиент
проверяет версию ответа и также сообщает о конфликте.

## Как проверить вручную

```bash
# недоступность: сервис не запущен
python src/main.py examples/input1.txt --transport http --url http://127.0.0.1:8080 ; echo "код: $?"

# таймаут: сервис отвечает с задержкой 3 с, клиент ждёт 1 с
python src/serve.py --port 8080 --delay 3      # терминал 1
python src/main.py examples/input1.txt --transport http --timeout 1 ; echo "код: $?"   # терминал 2
```

Автоматически эти ситуации проверяются тестами `tests/test_exceptions.py` и
`tests/test_pipeline_errors.py`.
