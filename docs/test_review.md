# Ревью набора тестов: мутационная проверка

Высокое покрытие показывает, какой код **выполнялся** тестами, но не то, что тесты **проверяют
результат**. Поэтому набор проверен мутациями: `tools/mutate.py` вносит в копию кода простые
изменения (`<` → `<=`, `and` → `or`, `+` → `-`, удаление `not`, изменение константы) и запускает
тесты. Если тесты проходят — мутант «выжил», то есть в тестах есть пробел.

## Результаты

|--------|---------:|------:|-------:|---------------:|
| До ревью | 138 | 120 | 18 | 87.0% |
| После добавления тестов | 138 | 135 | 3 | 97.8% |

## Что осталось после доработки

- `server.py, строка 46: константа 0 -> 1`
- `server.py, строка 49: константа 0 -> 1`
- `server.py, строка 49: Lt -> LtE`

Это эквивалентные мутанты: наблюдаемое поведение (HTTP-код ответа) не меняется, поэтому отличить
их тестом, не привязываясь к реализации, нельзя.

## Выводы

- Покрытие строк уже было высоким, но 18 мутантов выжили: тесты не проверяли тексты сообщений,
  значения по умолчанию, ответ `/health`, данные заглушек и повторный запрос при вводе.
- Для каждого пробела добавлен тест (`tests/test_review_gaps.py`); остальное — эквивалентные
  мутанты, которые не требуют тестов.
- Мутационную проверку стоит запускать перед выпуском версии, а не на каждый коммит (около
  минуты на 138 мутантов).
